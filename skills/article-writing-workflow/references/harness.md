# 按阶段目标执行的 Harness

本文件控制何时行动、如何验证、何时推进与如何恢复。九阶段目标以 SKILL.md 为准，制作细则以对应参考文件为准。它是当前 Agent 可以执行的文件协议，不表示已经实现自动调度器、状态校验服务或工具 API。

## 架构与职责

采用“阶段状态控制＋阶段内探索＋独立审核修正循环”。固定阶段入口和出口，允许在阶段内部按证据选择方法。

| 部件 | 负责 | 判断边界 |
|---|---|---|
| 当前执行者 | 恢复状态、选择下一行动、写作与修改、同步衍生成果 | 不能替人类批准，不能替独立审核人关闭问题 |
| 持久化成果 | source、knowledge-base、article 及已选视觉保存实际内容；working 保存状态、决定与引用关系 | 聊天摘要不能覆盖实际文件或真实批准记录 |
| 确定性工具 | 转换 HTML、渲染、校验值、链接及机械检查 | 成功运行不等于内容正确或已获批准 |
| 独立审稿／审图 | 对指定成品提供分级问题与修正验证 | 只审不改，不取得写作者的自评，不代替事实来源核对 |
| 人类 | G1 决定方向、G2 确认知识、G3 批准定稿 | 决定绑定实际展示的范围与版本 |

主执行者串行维护工作记录与成果，不同时派多个写作者修改同一基准。独立 Agent 仅在既有文字／图片审核节点调用；不为每个阶段新增角色。

## 每轮执行协议

1. **恢复**：读 working.md 顶部状态、对应确认记录及本轮相关成果；核对文件存在、内容和版本能否对应。新任务先执行 01，无材料时停在收集材料。
2. **选行动**：对照本阶段目标，选择一个能消除当前关键缺口的工作单元，如核实一个关键主张、补齐一章论证或修正一组相关 Q 项。没有缺口时检查出口，不为凑流程继续改稿。
3. **准备输入**：只加载本轮所需参考、来源和成果片段。开始依赖基准的制作前核对 G1／G2，独立审核前保存输入快照并计算校验值。
4. **执行并观察**：实际调用工具或读取成品，保留结果与错误。来源检索允许探索；格式转换和渲染复用现有脚本，不凭空声明存在某个 API。
5. **验证并记录**：把成果位置、目标证据、未解决项及下一行动写回 working；检查通过、目标达成和人类批准分别记录。
6. **推进或退出**：满足本阶段出口才推进。未达成则在当前阶段修正，或退回问题来源阶段。遇到 G1／G2／G3 时先提交可审成果，再等待真实决定；已授权且无依赖阻挡的工作继续执行。

一次工作单元可以跨多次工具调用；阶段通过后可在同一轮进入下一阶段，不强制每阶段结束对话。

## 阶段契约

下表补足进入条件、允许行动与失败路由，不重复 SKILL.md 的目标与达成证据。只有所选交付分支才生效。

| 阶段 | 进入条件与最小输入 | 主要行动与本阶段检查 | 推进条件／未达成时 |
|---|---|---|---|
| 01 输入 | 用户请求与实际材料 | 保留原文、辨识用途和公开边界，采用已有设置与默认值 | 可辨识主题且已记录关键未知 → 02；完全无材料 → 等待材料，不做虚构诊断 |
| 02 诊断 | 素材与任务设置 | 按主张核对来源、概念和论证，提出有证据的候选方向 | 诊断可定位、方向与缺口能供作者取舍 → 03；缺口列明，不强求此时全部消除 |
| 03 决策 | 已展示诊断、候选方向与取舍 | 提交 G1，记录作者选择、单篇目标与补充材料 | G1 明确且范围可辨 → 04；未决定时等待，已有明确决定不重问 |
| 04 优化 | G1 与作者评论 | 完整知识稿、证据关系、启发与适用条件，逐项回应评论，同步 MD／HTML | 完整候选知识可逐项核对 → 05；证据问题回 02，方向根本变化回 03 |
| 05 确认 | 已展示完整知识 HTML／MD 与未决项 | 核实关键事实问题已处理，提交 G2，保存批准版本 | G2 明确且关键事实无未决 → 06；作者退回则修 04，不将页面展示算批准 |
| 06 规划 | 已确认 B 版本与单篇目标 | 启用时制作并审核知识图解、嵌回知识稿；建立标题链及每章问题／依据 | 大纲推进主线；启用的知识图解已验证 → 07；图解关闭则跳过，知识变化回 04／05 |
| 07 生成 | B 版本、大纲及交付选择 | 完整正文 → 语言修订 → 独立文字审核与修正验证 → 已选文章视觉／PPT 与独立审图 | 正文及已选成果齐备，阻挡／必修已验证 → 08；文字未通过不先制作依赖它的文章配图 |
| 08 审核 | 当前成品、有效报告、目标与引用对照 | 核对目标答案所在位置、来源、嵌图衔接及同步，提交实际版本 G3 | G3 明确且阻挡／必修与待同步均清空 → 09；按问题退回 02／04／06／07，修正后再提交 |
| 09 交付 | G3 对应成品及已选交付清单 | 检查实际文件可打开、离线 HTML 一致，保存带来源和条件的知识摘要 | 所选成果与记录齐全才完成；缺文件留在 09 修复，实质内容问题退回对应阶段 |

07 内部顺序用于减少配图返工，06 知识图解仍以 G2 为依据，不受文章配图的文字先审条件限制。纯导出与排版修复无须重复请求 G3；改变实质知识或定稿内容按原 G2／G3 规则处理。

## 状态、观察与交接

继续使用 working.md，不另建一套 JSON 状态或重复日志。当前状态增加“执行状态”和“下一行动的输入”；输出文件在实际产生时才登记。

- **进行中**：有可执行的下一行动。
- **待人类决定**：已展示对应成果，缺 G1／G2／G3 决定；记录待决定事项与版本。
- **受阻**：材料、工具或依赖缺失；记录原因、可继续的独立工作及解除条件。不能仅因工作尚未完成就写受阻。
- **完成**：仅在 09 出口满足时使用；阶段内进展写“本阶段已达成”。

工具结果保留原始输出，不要求改造现有脚本的返回格式。在已有工作记录中简记四项观察：`结果（成功／警告／失败）｜说明｜实际成果路径及版本｜下一行动`。失败再加原因线索、重试前置条件和停止条件。脚本报错后生成的残留文件标为待验证，不当作成功成果。

上下文交接时保留：当前阶段／执行状态、目标证据与缺口、基准和成果版本、G1／G2／G3 对应范围、未解决 Q 与次数、待同步文件、下一行动及所需输入路径。详细内容留在原成果和报告中，不全文抄进摘要。跨上下文恢复后先核对这些输入再工作，不从 01 重跑。

## 修改后怎样失效与恢复

每次修改前沿用引用对照列影响位置；没有关系记录时检查实际引用，不能假定“没有影响”。只让受影响部分进入待验证。

| 触发 | 需要失效或重新验证的范围 | 保留什么 |
|---|---|---|
| 改核心问题／读者／方向 | 检查 G1 仍否覆盖；必要时重新 G1，再核对知识稿、大纲与后续成果 | 原材料、来源及仍适用的决定 |
| 改主张、数字、案例结果、适用范围 | 更新知识稿，按规则重新 G2；引用它的正文、图、图说、译版及 PPT 待验证；定稿实质变化再 G3 | 未受影响来源与已核实关系 |
| 改措辞／段落，事实立场不变 | MD／HTML 同步；对改动及必要上下文作文字复审；相关图文语境核对 | 原 G2；未变部分的有效审核结论 |
| 改 PNG／图源／字体／尺寸或翻译图文 | 对实际改图重跑渲染、适用检查和独立审核，检查衍生文件与图文一致性 | 未改图的有效报告；知识稿原图与文章变体分开 |
| 仅重建 HTML／移动插图 | 核对离线内容、显示、图说及引用；新增图说交文字审核 | 没变的正文和图的版式审核结论 |

审核记录绑定输入快照、版本和校验值；当前文件不同不等于必须全文重审，应先辨识差异，再按“工作状态与审核记录”复用或扩大范围。文件名和版本号相同不能作为内容未变的证据。

## 失败恢复与停止条件

| 失败 | 恢复行动 | 何时停止依赖此项的工作 |
|---|---|---|
| 来源不可访问或不足以支持结论 | 找原始／官方替代来源；不能核实则缩小、删除或标记未知，交作者取舍 | 关键事实仍未决时不能通过 G2 或制作将其当作确定事实的内容 |
| 渲染／检查启动失败 | 核对运行时、路径和依赖，保留错误；有明确新线索后再重试 | 同一输入与环境不作无变化重跑；需要安装或额外权限时报告具体缺项，继续无依赖工作 |
| 工具超时、部分产物或审核中断 | 检查已有文件与日志，确定实际完成范围；只补未完成或无有效验证的部分 | 未收到报告不能算通过，不覆盖旧报告，不因中断重置问题计数 |
| 同一阻挡／必修两轮未解 | 回看材料、论证、文案或结构原因，改变修正方法 | 同一问题第三轮验证仍未解，按原规则交回人类；不改编号绕过上限 |
| 缺独立审核能力 | 完成可做的准备，保留待审核状态及所需输入 | 不以主执行者自审冒充独立审核，不将依赖该审核的阶段标为通过 |
| 记录与文件或人类决定不一致 | 对照真实决定、版本快照和实际差异，恢复可证明的状态 | 不猜测批准；仅当确实无法确定必要范围时向作者澄清 |

独立文字审核保持成品盲读边界；来源与作者立场由执行者另行对照。图片审核需要参照正文及实际 PNG；输出范围、输入和报告命名沿用主 Skill 对应规则。

## 验证流程升级

修改本 Skill 后，用以下情境检查决策是否正确；这是维护时的走查，不是每篇文章新增审核表，也不是已经完成真实写作测试的证明。

| 情境 | 应有行为 | 错误信号 |
|---|---|---|
| 用户只给写作意图，无材料 | 整理设置后等待原材料 | 虚构诊断、来源或文章 |
| G1 前用户说“继续”，未选择已展示方向 | 按真实回复判断是否足以确定方向；不批准未展示内容 | 直接生成并宣称知识已确认 |
| G2 已确认，选择仅文章 | 跳过图解和文章视觉；保留独立文字审稿 | 等待 PNG、强制建 visuals 或跳过文字审核 |
| 文章已审，随后改一个数字 | 回知识基准并核对重新 G2，按引用关系更新全部受影响成果 | 只改正文或沿用旧校验值 |
| 已审知识图原样复用，文章语境改变 | 看实际 PNG 并核对新语境，保留有效版式结论 | 因已审完全跳过核对或无差别重做全部图 |
| 渲染失败但目录已有旧 PNG | 分辨旧成果与本轮未完成项，保留错误 | 把旧 PNG 算作本轮成功 |
| 审核三轮仍有同一必修项 | 保留问题计数并交人类决定 | 换 Q 编号、放宽级别后宣称通过 |
| G2 后换上下文，缺新用户反馈 | 恢复当前阶段和有效批准，再做下一行动 | 重问已确认 G2，或把沉默记为 G3 |
| G3 批准后导出文件缺失 | 留在 09 补导出并检查；不重复批准未改内容 | 文件不存在仍宣称交付完整 |
| 用户要求定稿后日文 | 从批准 A 版翻译、润色、对照与独立审核 | 翻译未批准稿或只跑 lint 就声称翻译准确 |

实际运行后，从已有记录观察：所选交付是否完成、同一问题修正次数、文字审核后发生的配图返工及原因、恢复时能否接续正确行动。没有足够可比样本时不宣称效率提高，不强制打卡或新增评分。
