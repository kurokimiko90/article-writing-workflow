# 独立审核协议

首次派发及复审前读取本文件；报告命名、快照、校验值与 Q 项追踪仍按主 Skill“工作状态与审核记录”执行。审核标准分别以 `<skill>/agents/text-reviewer.md` 和 `<skill>/agents/figure-reviewer.md` 为准。

### 配图独立审核（第 06 阶段知识图解、第 07 阶段文章配图）

制作者自己看图容易放过问题（2026-10-22 用户指定）。知识图解在嵌回知识稿前独立审图，文章配图完成后独立审图；已审图复用按第 5 条处理：

1. **派发方式**：Agent 定义正本是本 Skill 的 `agents/figure-reviewer.md`。用 `install.sh` 安装后，Claude Code 可用 `subagent_type: "article-figure-reviewer"` 派发；该类型不可用时，改派全新上下文的子 Agent，先完整读取该文件并执行。不可由制作者自审代替。输入为：文章目录、审核阶段（kb／article）、参照正文路径与 B／A 版本、视觉版本、语言、PNG 及可编辑来源清单、当前明确采用的风格、报告输出路径。知识图解参照已确认 knowledge-base.md，文章配图参照 article.md；复用／复审另附上一轮报告、文件校验值和本轮变化清单，不附制作过程、自评或“脚本已通过”等说明。报告按“工作状态与审核记录”命名。
2. **审核标准**：以 Red Dot／D&AD／ADC／Tokyo TDC／Good Design 得奖选手的眼光，逐张直接读图，按一眼讯息、结构表达、视觉层级、字体排版、留白网格、色彩系统、图文一致七个面向给分级问题与具体改法，并做全组审视。规则以该 Agent 文件为准。
3. **处理结果**：报告中的 R 编号连同报告路径映射到 working.md 的 Q 项。阻挡与必修全部修正后重跑对应渲染和检查，再派发审核验证；可选项记录取舍。同一阻挡／必修问题连续修正验证最多三轮，两轮卡住先检查文案或结构原因，第三轮仍未解决时交回人类决定。这里按问题追踪修正次数，不以累计报告编号 rNN 判断超限；新阶段或新问题不继承无关旧问题的修正次数。
4. **中日两版**分别审核；日文图文字较长，常出现中文版没有的溢出与断行问题。翻译版的图**不重画**：沿用原文版已修好的 HTML 结构，只替换文字（`lang` 改成对应语言），再跑 build；派发审核时把原文版 diagrams 目录一并交给审图 Agent 做结构对照，figure-lint 用 `--source <原文版 diagrams>` 检查菱形与卡片数量（2026-10-26：日文版 05 独立重画后少了第二次审查）。
5. **按变化复审与复用**：首次没有有效报告的图全部审核。后续输入分为“新增／改图”“原图未改但引用正文或图说改变”“原样复用”三类；具体规则见“工作状态与审核记录”。独立审图 Agent 对第一类重做七面向检查，对第二、三类直接看 PNG 并核对当前语境与图文一致性，不重评未变化的版式；仍未解决的上一轮问题必须验证，不能靠列入复用清单跳过。全组审视仅在变化影响全组时更新。文章需要改图时先另存变体，不能覆盖知识稿原图；跨语言替换文字属于改图，须检查译版版式与原文结构。
6. **正文修改另列：** 审图报告中“改正文就能解决”的项目单独列出，标明对应知识稿或文章位置，由作者决定改图还是改文。涉及实质知识变化仍按 G2／G3 处理，不以修改正文迁就错误图片。
7. **不是决策点**：独立审图不代表 G3，分数不代表人类批准。G3 提交时附最新审图报告路径与未解决项。

### 文字独立审稿（第 07 阶段语言修订后、文章配图前）

作者读自己的文章会自动补上缺的定义和前提，读不出看不懂、重复和生硬（2026-10-27 用户指定，把人工审文字的做法固定成独立 Agent）。完整初稿经语言修订后、文章配图前，派发独立审稿 Agent；仅文章模式同样执行：

1. **派发方式**：Agent 定义正本是本 Skill 的 `agents/text-reviewer.md`。Claude Code 可用 `subagent_type: "article-text-reviewer"` 派发；该类型不可用时，改派全新上下文的子 Agent，要求它先完整读取该文件并按其执行。不可由写作者在当前上下文自审代替。只交给它：`article.md` 路径及 A 版本、语言版本、按“工作状态与审核记录”命名的报告输出路径；翻译版另附原文版 `article.md` 路径；复审另附上一轮报告及改动范围。不附 working.md、知识稿、写作过程或自评，保持“完全不知情”。
2. **审核内容**：看不懂、前置引用、矛盾、重复、啰嗦、术语不统一、生硬、口径过头八类，逐条给分级问题（阻挡／必修／可选）、行号、原文片段与可直接替换的改法。规则以该 Agent 文件为准。
3. **处理结果**：T 编号连同报告路径映射到 working.md 的 Q 项。阻挡与必修全部修正，改过的段落再派发复审；同一阻挡／必修问题连续修正验证最多三轮，第三轮仍未解决时交回人类决定。累计报告编号 rNN 不代表该问题修正次数，新问题不继承无关旧问题的次数。可选项逐条决定采用或记录不采用理由。
4. **中日两版**分别审核；日文版另查日语语感，并与中文版结构对照。文字改动要两版同步，改完再跑 build，图号与正文引用须一致。
5. **改图与改文分开：** 报告里涉及图的问题交给配图流程，不在审稿轮里改图。
6. **不是决策点**：独立审稿不代表 G3。G3 提交时附最新审稿报告路径与未解决项。
7. **嵌图后检查**：第 08 阶段核对插图位置、图说重复或新增结论、图号及前后引用。配图过程中改过正文时，将改动处和理解它所需的上下文交独立文字审稿 Agent 复审；新写的图说一并检查。未改的正文沿用上一轮结论，不固定增加一轮全文审稿；文章结构或主线大幅变动时扩大到受影响章节，必要时重审全文。阻挡与必修项仍须解决并验证后才提交 G3。
