# Article Figures（HTML 文章配圖）

## 產出

- `<輸出目錄>/src/`：`base.css`（設計規格）、`icons.js`（共用圖示）、每張圖一個 HTML、`shoot.sh`
- `<輸出目錄>/*.png`：封面 1280×670 @2x、內文圖 1600×1000 @2x
- 給使用者的「日文校對清單」
- 預設輸出目錄：使用方項目的 `exports/images/<文章短名>/`

## 預設風格：warm-paper（2026-10-14 起，使用者指定「下次自動用這個風格」）

**除非使用者另外指定風格，一律以 `templates/warm-paper/` 為起點**（範本：`frames.html` 單檔多圖、`shoot.sh`、`assets/miko/` 吉祥物貼圖）。
來源：作者過去的文章配圖系列（範例內容已去識別化，見 `templates/warm-paper/frames.html`）。

- 做法：`cp -R <本 Skill 目錄>/templates/warm-paper/ <輸出目錄>/`，改寫 `frames.html` 的各 `<section class="f" id="fN">`，`shoot.sh` 的 `names=()` 對應改名，`bash shoot.sh [N…]`。
- 單檔多圖：`frames.html#fN` 只顯示該圖；連線在 `draw()` 內依 `getBoundingClientRect` 相對 section 畫。
- 畫布：內文 1200×675 @2x、封面 1280×670 @2x；內距 40/64/52px。
- 背景：暖紙色 `#F6F2EA`＋右上杏色、左下萊姆 radial-gradient＋紙紋 noise（`.f::after`）。
- 標題：每張內文圖有一句短標題（44px/900），後半句用 `<mark>` 萊姆螢光筆。這覆蓋下方「內文配圖不放大標題」的規則。
- 元件：圓角 18px 卡片＋柔和陰影（無邊框）、圓形 badge 圖示（lucide@0.469.0 CDN；杏色/青綠/萊姆/墨黑四種底）、重點卡用 `--mark-soft` 底＋萊姆內框。
- 色票：ink `#1F2A27`、teal `#11645B`（事實/連線）、mark `#D9F05B`（重點，每張 1 處）、apricot `#F2A97E`。
- 字體：Zen Kaku Gothic New，`font-feature-settings:"palt"`，字距 .02em（假名用 .04em 會太鬆）。
- 字級（1200 畫布）：hl 44／lg 30／md 20／sm 16（最小值）。在此風格下，這組 token 取代下方 1600 畫布的字級表。
- Miko 吉祥物：右下或右上角，高約 100–124px，不可蓋到內容；不一定每張都放。
- 文章是簡體中文時，換成 `Noto Sans SC`（Google Fonts），並把 `.f` 的 `font-feature-settings` 改成 `normal`、字距 .03em（palt 會把中文標點「，：、」擠在一起）。

## 設計規格（不可違反）

### 字體
- 全組只用一個字族（預設 Zen Kaku Gothic New；若同系列文章已用其他字族，跟隨該系列）。
- 層級只靠字重：900 標題／700 內容／500 補充。
- 不用等寬字、不用英文小標當裝飾。

### 字級（以 1600px 畫布、文章內約 700px 顯示換算）
| token | px | 用途 |
|---|---|---|
| --fs-hero | 96 | 結語、封面主句（封面可 92–104） |
| --fs-h | 56 | 區塊標題 |
| --fs-lg | 40 | 重點卡片 |
| --fs-md | 32 | 欄標題、清單、一般卡片 |
| --fs-sm | 28 | 補充說明（**最小值，任何文字不得低於此**） |

只能用這 5 級，禁止寫死其他字級。

### 呼吸感
- 畫布外圍留白 ≥ 84px；卡片內距 ≥ 32px；卡片間距 22–28px；內文行距 1.45–1.55；字距 .04em。
- 一張圖一個訊息。放不下時：先刪重複元素，再拆圖，最後才縮字（不得低於 28px）。

### 顏色語意（固定）
- 青綠實線＝事實；玫紅虛線＋淡底＝推測；墨黑＝中性；暖黃＝行動或正向重點，**每張最多 1 處**。
- 推測區不用斜線填充（難讀）。

### 內容規則
- 內文配圖**不放**大標題、圖號、底部說明、圖例（文章本身就有）。封面例外。
- 每個資訊單位最多 1 個圖示；不加光暈、星星、網格等裝飾。
- 作者頭像（若有）只放 2–3 張（封面、人物相關圖、結語），必須有眼睛、視線指向主題物。

### 可視化原則
- 先找「關係」再排版：對比、因果、順序、層級、距離、分支收斂，用位置、連線、大小、顏色來表達，文字只負責標籤。
- 每張圖的文字量：一個主訊息＋最多 6 個標籤／短句；超過就拆圖或改成圖形。
- 每個資訊單位配 1 個圖示（不超過 1 個），讓讀者不讀字也能先辨識類別。
- 圖示統一：線條風格 24×24、線寬 2、只用顏色語意中的色，全部收在共用 `icons.js`。
- 數字、步驟、比例優先做成圖形（階梯、刻度、進度、節點），不要只寫成句子。
- 為了可視化而刪減或改寫的文字，一律列進校對清單（△＝縮短、附原句），不得悄悄刪掉。

## 流程

### 1. 讀文章 → 分鏡
- 抽出 5–7 個核心訊息，每個對應一張圖，選一種構圖：對比（A≠B）、三欄（推測｜現象｜事實）、階梯、放射圖＋步驟、分支收斂、清單、結語宣言。
- 列出每張圖要用的原文句子。**盡量用原文**；需要新寫的句子標 ★。

### 2. 建骨架
- 每輪修改前備份：`cp -R src *.png _backup_YYYYMMDD[b,c…]/`
- `base.css` 寫入上述 token；`shoot.sh` 用：
  ```bash
  "$CHROME" --headless=new --hide-scrollbars --force-device-scale-factor=2 \
    --window-size=W,H --virtual-time-budget=8000 --screenshot=out.png file://…
  ```
  網路字型可能卡住 → 每張加逾時（60 秒）並重試 1 次。

### 3. 排版技巧（踩過的坑）
- 日文換行一律手動 `<br>` ＋ `white-space: nowrap`，不要交給瀏覽器自動斷行（會掉單字、孤字）。
- SVG 改寬度時 **viewBox 要一起改**，否則整張被縮放、和 HTML 標籤錯位。
- 連線用 JS 依 `getBoundingClientRect()` 的實際座標畫，不要寫死。
- 連線的**語意**要對：多對多就連到括線，不要全部只連到某一項。
- 先算寬度：字數 × 字級 × 1.04 ≤ 容器內寬，算不過就斷行或加寬欄位。

### 4. 截圖優化迴圈（每次產出後自動執行，不等使用者要求）

**品質標準**：以 Awwwards / Webby Awards / FWA 得獎作品的水準為目標。透過自我檢查，反覆自行提升品質，直到達到該標準為止。

每一輪依序做 4 件事：

**A. 截圖**：`bash shoot.sh`，再用 Read 逐張看 PNG（每張都要看，不可抽查）。

**B. 硬性檢查**：任何一項沒過，就要先修，修完才能評分。
- [ ] 任何文字 ≥ 28px，縮到 700px 寬仍可讀
- [ ] 沒有重疊、溢出、孤字、不自然斷行
- [ ] 只用 1 個字族、5 級字級
- [ ] 顏色語意正確，連線和箭頭的意思與文章一致
- [ ] 每張暖黃 ≤ 1 處、每個資訊單位剛好 1 個圖示
- [ ] 每張文字量：1 個主訊息＋最多 6 個標籤／短句

**C. 得獎水準評分**：每項 1–5 分，逐張評分，並寫下扣分的具體理由。

| 維度 | 5 分的樣子 |
|---|---|
| 概念 | 一眼看懂這張圖要說的一件事，構圖本身就是比喻（例如階梯＝離事實越來越遠） |
| 字體排印 | 層級清楚，3 秒內知道先讀哪裡；字距、行距、斷行都經過調整 |
| 網格與對齊 | 每個元素都對齊到同一套網格；左右區塊的上下緣對齊；間距有固定節奏 |
| 呼吸感 | 留白是刻意設計的，不是剩下的；內容不擠，也不會空掉一大塊 |
| 色彩 | 語意一致、克制，重點色只出現在真正的重點 |
| 細節 | 線寬、圓角、圖示粗細全組一致；沒有半像素錯位或錯位的連線 |
| 系列一致性 | 全部放在一起，看得出是同一套系統 |
| 可視化 | 先看圖形就懂 7 成意思；文字只是標籤，沒有成段的句子 |

**D. 判斷**
- 任何一張有任何一項 < 4 分：針對最低分的項目修改，回到 A。
- 全部 ≥ 4 分，而且這一輪沒有再找到可改進的地方：結束。
- 每一輪記錄「發現了什麼問題 → 怎麼改的」，交付時列給使用者。
- 上限 6 輪。到上限還沒達標，就停下來，回報還差哪些項目、卡在哪裡，不得硬說已達標。

**誠實原則**
- 分數是自評，不代表外部評審的結果。交付時說「自評各項 ≥ 4 分」，不說「已達到得獎水準」。
- 沒看過的截圖，不得寫進「已檢查」。

### 5. 交付
- 回報每張改了什麼、每輪自檢修掉哪些問題。
- 附「日文校對清單」：逐張列出圖中全部文字，★＝新寫，△＝從原文縮短（附原句）。
- 輸出的圖檔不屬於專案原始碼，不需要更新專案文件。

## 常見修改要求 → 對應做法
| 使用者說 | 做法 |
|---|---|
| 字太小 | 以 --fs-sm 28px 為下限重排；刪小字裝飾 |
| 太亂 | 做減法：刪裝飾→刪重複→每單位 1 圖示 |
| 要活潑/溫暖 | 加暖黃 1 處、頭像；不要加光暈星星 |
| 文字太多/不夠直覺 | 套「可視化原則」：關係改成圖形，文字縮成標籤，刪減列進校對清單 |
| 字體統一 | 一個字族＋5 級 token |
| 要呼吸感 | 加大留白與間距，必要時降一級字級 |
| 對齊差 | 左右區塊垂直置中、上下緣對齊、節點等距 |
