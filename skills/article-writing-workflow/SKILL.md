# 文章撰写与知识沉淀

> **路径约定：** 本文中 `<skill>` 指本 Skill 目录（即本 SKILL.md 所在目录）。`scripts/`、`references/`、`agents/`、`vendor/` 等相对路径都以它为基准；`<skill>/../article-figures/` 是同一仓库中的封面与叙事图 Skill；`vendor/` 下是第三方 Skill 副本（来源见 `vendor/SOURCES.md`）。

这是独立的专用 Skill。按用户确认的九阶段流程完成文章及所选视觉交付，由专用 Agent `article-knowledge-editor` 执行，或由当前 AI 直接执行本 Skill。人类掌握内容方向、事实确认及最终决策。

本 Skill 已将参考材料中相关的写作、查证和知识整理方法提取为内部规则。视觉制作是用户指定的例外，按用途分工使用两个制图 Skill：
- **结构图解**（流程、结构、对比、判断、循环、层级等说明型图）：读取并使用 `<skill>/vendor/diagram-design/SKILL.md`，套用 profile `~/.diagram-design/profiles/warm-paper.md`。用于 G2 后的“知识图解”与第 07 阶段的说明型配图（见“知识图解”与“配图分工”）。
- **叙事配图**（封面、开场、氛围、收尾等非结构图）：读取并使用 `<skill>/../article-figures/SKILL.md`，根据已完成的故事文章制作。

定稿后的日文翻译是另一个用户指定例外：译成日文后，必须读取并使用 `<skill>/vendor/yomiyasu/SKILL.md` 润色日文（见“定稿后日文翻译”）。

配图独立审核是本 Skill 自带的独立 Agent：出图后必须派发 `agents/figure-reviewer.md`（本 Skill 目录内，正本），由它直接读取 PNG、以设计大赛得奖选手标准审核（见“配图独立审核”）。文章写完后还必须派发 `agents/text-reviewer.md`，以完全不知情的读者视角审文字（见“文字独立审稿”）。其余环节不加载或调用其他 Agent／Skill。

## 目标与完成判断

### 整体目标

帮助作者把真实材料整理成有依据、表达原意、目标读者能理解的文章，并保留可复用知识。

### 单篇目标

开始时依据目标读者、文章目的、核心一句话及读后结果，整理一句可检查的目标：

> 让【目标读者】在读完后能够【理解、判断或完成的具体事情】，文章需要讲清【核心问题及必要条件】；通过【正文中可定位的答案、解释、做法或判断依据】核对。

单篇目标沿用已有任务设置，不新增问卷或确认点；在 G1 随方向一并决定。材料不足时提出候选并标明缺口，不能把默认值当作作者批准。

### 阶段目标与达成证据

| 阶段 | 本阶段要达成的目标 | 用什么证据判断达成 |
|---|---|---|
| 01 输入 | 让作者与 AI 对写给谁、解决什么问题、可用材料和公开边界形成明确的任务理解。 | 能从任务摘要指出目标读者、核心问题、预期读后结果、可用素材与公开限制；未知及采用的默认值明确，原始材料可找回。 |
| 02 诊断 | 让作者看清材料的价值、可信程度与关键缺口，获得决定方向和素材取舍的依据。 | 影响方向的关键主张有依据或明确标为未知；问题定位到材料，说明影响和具体改法；候选方向能对应材料价值与证据，不只罗列错误。 |
| 03 人类评论与决策 | 把候选方向与取舍变成作者明确选择的写作方向，避免后续优化依赖 AI 的猜测。 | 作者已对展示的方向与关键取舍作出 G1 决定；核心问题、预期读后结果、保留或待补素材及未决事项有记录，后续优化知道以什么为准。 |
| 04 依评论优化 | 把选定方向下的材料整理成完整、可核对的知识，明确文章值得读的启发及其成立条件。 | 影响知识稿的评论有处理结果或未决标记；事实、主张、案例、证据及限制可对应；启发与价值有材料依据；作者能逐项核对完整知识，而不必自行补全省略前提。 |
| 05 人类确认基础知识 | 确立作者认可的知识与表达边界，使故事、正文和图能依据同一份已确认内容展开。 | 关键事实无未解决项；作者明确 G2 确认所展示版本的事实、主张、启发、适用与公开范围；后续引用能定位到该知识基准，未确认内容不混入。 |
| 06 故事与视觉规划 | 让知识关系可理解，并把知识安排成能回答核心问题、逐章推进至已确认启发的阅读路径。 | 所选知识图经验证后能与知识稿对应并已嵌回；大纲说明每章回答什么、用什么依据、如何衔接且无无意重复；标题链能辨识主线；可选图解未启用时按设置跳过。 |
| 07 生成 | 让目标读者仅凭文章即可理解核心观点及必要依据、条件，并通过所选视觉理解相应关系。 | 完整正文回答单篇核心问题并提供预期读后结果所需解释；语言修订保留作者原意；独立文字审稿的阻挡及必修已验证解决后再做文章配图；所选视觉有正文依据、真实文件和检查记录，无补造事实。 |
| 08 品质审核 | 验证当前成品达成单篇目标、保留作者原意且无未解决的阻挡或必修问题，再由作者决定是否定稿。 | 按单篇目标逐项指出正文中的答案、解释、做法或判断依据；所选视觉与正文一致，最新文字和图片问题已验证解决、待同步项无遗漏；作者对实际成果版本明确作出 G3 批准。 |
| 09 交付与沉淀 | 让作者拿到可使用、可追溯的成果，使有依据的知识和真实经验能在明确条件下再次使用。 | 所选交付文件及链接可打开，HTML 与来源内容一致；知识摘要和案例无需依赖本次对话即可理解，附证据、条件、限制、确认状态和版本；缺项如实列明，不把未完成交付记为完整。 |

执行下方九阶段时，以对应目标选择和检查工作。动作完成、文件生成、检查脚本通过或自评分数，均不能单独证明目标达成。沿用 working.md 的当前状态与审核记录，简记当前目标的达成证据、缺口及下一步，不另建评分表；仅检查本阶段已具备的成果，不提前要求下一阶段的成品。

目标判断必须对应实际材料、正文、图面、审核验证或人类决定；未做真实读者测试时，只能陈述文本与独立审稿提供的证据，不能声称读者已理解。不以传播、点赞或所有读者喜欢作为流程可保证的结果。只有动作完成但目标仍有关键缺口时，继续修正或按既有审核边界退回；人类决策仍只在 G1／G2／G3，复审次数与交付选择沿用原规则。

## 开始与默认设置

1. 接收原始材料，保留原文。未提供材料时，只整理已有任务设置，再请用户提供材料；不要生成虚构诊断或文章。
2. 读取 [任务选项与默认值](references/defaults.md)。优先级：用户最新明确指示 → 材料中明确的任务说明 → 默认值。空白、未选择或空白自定义值使用默认值，不逐项追问。
3. 提交简短任务摘要，标明用户指定、材料明确说明或默认。不为默认设置增加确认关卡；直接开始诊断。
4. 只追问影响方向、关键事实或公开范围的问题。用户明确要求优先于通用 Skill 建议。

## 九阶段

| 阶段 | 执行内容 | 产出与完成条件 |
|---|---|---|
| 01 输入 | 整理任务设置、原始材料及来源 | 可辨识主题的素材包、任务摘要、关键缺口 |
| 02 诊断 | 检查事实、逻辑、概念、理解障碍及内容价值；区分事实、经验、推论、未知 | 简洁诊断表、问题及具体改法；必要查证依任务设置进行 |
| 03 人类评论与决策 | 集中提交方向、关键问题与素材取舍；接受保留、修正、深化、删除、待确认 | **G1：人类明确决定方向**，记录评论与补充材料 |
| 04 依评论优化 | 整合补充，修正知识结构、证据及表述，逐项处理评论；提炼“启发与价值” | HTML基础知识稿（含启发与价值）、修改摘要、待确认事项 |
| 05 人类确认基础知识 | 提交完整HTML知识稿，包含目的、事实、核心观点、启发与价值、案例、证据、适用条件及公开范围 | **G2：人类确认知识基准**，保存对应版本；关键事实无未解决问题 |
| 06 故事与视觉规划 | 按已确认知识稿逐章制作知识图解，机械检查、逐图查看、独立审图并修正验证后嵌回知识稿；再以已确认的“启发与价值”为落点建立故事主线、大纲及候选视觉位置 | 图文完整的知识稿 MD＋离线 HTML、知识图解 `visuals/diagrams/`（PNG＋HTML＋README）、审图报告及大纲；最终文章配图依据完成的故事文章 |
| 07 生成 | 完整初稿 → 按 methods.md“语言修订与作者表达校准”修订 → 独立文字审稿、修正与复审 → 文章配图：说明型图用 diagram-design（可沿用并按全文修订知识图解），封面与叙事图用 article-figures；出图后独立审图，PPT按所选格式生成 | 完整文章、文字阻挡与必修项经验证解决、真实视觉文件、图说／必要备注明确，图文一致 |
| 08 品质审核 | 先收回独立审图报告与独立审稿报告并修正阻挡／必修项；AI 再核对来源、逻辑、可读性、故事节奏、完整性与视觉，先修正再提交人类 | **G3：人类批准定稿**；阻挡及必修问题已解决 |
| 09 交付与沉淀 | 保存定稿、所选视觉、摘要、可重用案例、来源及版本记录 | 实际文件可打开，知识可独立理解且可追溯 |

默认按顺序推进。已经确认且未改变的事项沿用，不要求重复确认。人类新消息是当前流程的反馈，除非明确更换任务。

## 三个人类决策点

- 在 G1、G2、G3 提交具体成果及需要决定的事项；记录决定对应的版本或文件。
- 空白、时间经过、沉默、默认值以及一般性的“继续做”不等于对未展示成果的批准。用户已明确认可所展示成果，则沿用该授权，不重复询问。
- 等待决策时结束当前轮次，说明下一步并保留待确认事项；可整理已确认材料，不生成依赖未确认内容的成果。
- G2 后新增或改变实质主张、数据、案例结果或适用范围，更新基准并重新确认；纯措辞、段落和排版调整无需重复 G2。
- 定稿后的实质内容修改或重要视觉结论变化需再次 G3；批准始终对应实际成果版本。

## 启发与价值

第 04 阶段起，基础知识稿必须有“启发与价值”一节，按 [本 Skill 的执行方法](references/methods.md) 的“启发提炼”产出，并随知识稿在 G2 确认。它回答“读者为什么值得读、读完能带走什么”，是第 06 阶段故事主线与结尾的依据。

- 每条启发标明依据的 C／E／K 编号，区分作者原话与 AI 推论；不能超出证据。
- 必含：一句话核心启发、新理解（常见认知与本案差异）、可迁移做法、适用前提与代价、建议故事主线。
- G2 后文章的核心句、转折与结尾建议须能对应到这一节；文章写出新的启发时，回写知识稿并按 G2 规则处理实质变化。

## 内容与审核边界

- 不补造事实、对话、心理活动、案例过程、成果或数据。假设示例明确标注，不当作真实案例保存。
- 主张不能超出证据；作者观察和推论保留身份及适用条件。关键内容无法查证时删除、缩小表述或交回人类决定。
- 不以故事性掩盖证据缺口；不强制人物弧线、英雄旅程、第一人称或书籍结构。
- 重要主张、证据和案例可用 C／E／K 编号关联；小文章也可用章节与来源链接，只需保持可追溯。
- 问题分为阻挡、必修、可选，以 Q01、Q02 编号记录在 working.md；状态按“新发现 → 修改中 → 待验证 → 已解决”推进，没有验证结果不得标为已解决。不采用的建议保留理由。
- 每轮先在 working.md 顶部更新当前阶段、版本、确认状态、未解决项、待同步项及下一步。修改前按引用对照列出影响位置；验证完成后才清除待同步项。各项只写真实状态，没有则写“无”，未选择的交付项写“不适用”。报告、问题映射及复审范围按“工作状态与审核记录”统一记录。
- 按下表九个面向判断退回阶段：

| 面向 | 通过标准 | 退回阶段 |
|---|---|---|
| 事实 | 关键主张有依据，来源与情境正确，未知已标示 | 02 查证／05 确认 |
| 逻辑 | 前提、证据与结论一致，反例与限制清楚 | 04 知识稿／06 架构 |
| 完整性 | 回答文章的主要问题，步骤可理解 | 06 架构／07 初稿 |
| 可读性 | 目标读者能理解概念、例子及操作 | 07 初稿 |
| 故事节奏 | 结论在标题下先给出；标题串成问答链，只看标题能读懂主线；各章提供新内容并推进，不重复揭晓 | 06 架构／07 初稿 |
| 语言韵律 | 长短、疏密与停顿自然，无机械交替或刻意碎句，原意与条件完整 | 07 语言修订 |
| 作者声音 | 符合作者立场与已指定的表达方式 | 07 初稿 |
| 视觉一致性 | 图文数据、标签、用词与结论一致 | 07 配图（依最新全文重新分镜） |
| 交付品质 | 文件、链接、字体、图说及排版正常 | 07 制作／09 交付 |

- **修改连动：** 第 07 阶段写出文章后，在 working.md 建立“引用对照”，记录每个 C／E／K 编号被哪些章节段落、图号、PPT 页引用，以及涉及的数字。之后知识基准、文章或视觉中任一编号的内容或数字改变时：
  1. 先查引用对照，列出所有受影响的段落、图、图说、替代文字、讲者备注及日文版。
  2. 每个受影响位置在审核表开一个 Q 项，状态设为“待验证”，注明来源编号。
  3. 数字改变时，正文、图表、图说、替代文字、讲者备注逐一核对，不只改一处。
  4. 全部验证后关闭 Q 项，更新引用对照与版本记录；实质主张改变仍按 G2／G3 规则重新确认。
  引用对照只记录实际引用，不预先填写。
- **修改连动检查（2026-10-22 用户指正）：**
  1. 改标题后逐章核对标题与正文是否相符，不只换字；标题是问句时，章首第一句先回答；章名改掉后，承接旧标题的过渡语（如“补上：”）一起改。
  2. 删段落时，一并检查只为该段服务的图与图说，问作者是否同删；删图或插图后，正文、图说、alt 的图号连续重排，目录 `#sec-` 锚点同步重排。
  3. article.md 与 article.html 同步修改；有日文版时同一轮同步修改日文版的 md 与 html，不等作者提醒。
  4. 日文版修改后跑 yomiyasu lint 与 diff；自己新增的句子引起的新警告必须修掉，分数不得低于修改前。
- 每轮记录问题、修改及验证结果。两轮仍卡在同一问题时检查材料或结构原因；自评分数不代表事实核对或人类批准。

## 专用执行方法

诊断和写作时读取 [本 Skill 的执行方法](references/methods.md) 中相关部分。配图部分定义如何将故事文章交给用户指定的 article-figures Skill；制图规范读取其当前文件，避免复制旧版本。PPT和知识保存仍按本 Skill 内部方法执行。

- 每章一个主要任务，以具体问题或有依据的实例开场，用证据支撑观点。
- 句子与段落有自然的长短、疏密和停顿变化；按内部方法的“语言节奏与韵律”写作，并在第 08 阶段通读检查，不机械规定长短比例。
- 初稿完成后按 [执行方法](references/methods.md)“语言修订与作者表达校准”全文检查、按问题修改，再交独立文字审稿；不为“去 AI 味”强改自然段落，不新增细节或增强立场，修订后对照核对事实、重要信息与限定条件。
- 有真实参考文章时提取句长、语气、术语和转场偏好，否则使用默认语气。
- 关键证据不足且允许查证时直接用搜索、网页读取工具核对，保存来源与不确定性。
- 文章配图按“配图分工”选用 diagram-design 或 article-figures；先完整写好故事文章，再按全文的主线、章节及实际句子分镜，不能只根据基础知识稿生成（知识图解是知识稿的图，不等于文章配图，沿用时须按全文核对）。数量遵循任务设置，默认约每 10 个显示行一张、连续 10 行以上无图须补（细则见 `references/methods.md`“配图密度”）；风格和制作规范遵循指定Skill的当前版本。
- PPT 直接用可用文件生成工具制作真实 PPTX／PDF，不将逐页文字当作文件交付。
- 知识直接保存为本地 Markdown，附来源、条件、限制和确认状态；需要时在用户指定资料中去重。

不派发给通用写作、研究、视觉或知识管理角色。除用户另有指示，专用 Agent 自行完成流程。不添加营销、SEO、Bot、自动排程、跨存储同步或系统开发工作，不修改参考 Skill 与全局角色。

### 知识图解、配图分工与流程实例图

第 06 阶段知识图解及第 07 阶段文章配图制作前读取 [视觉制作细则](references/visual-production.md)。该文件保留知识图解、warm-paper 构建与检查、配图分工、交付及实物模拟图的完整要求。所选视觉通过机械检查、逐图查看及独立审图后嵌回对应知识稿或文章；文章改图先另存变体。

### 配图独立审核与文字独立审稿

派发或复审前读取 [独立审核协议](references/review-protocol.md)。第 06 阶段知识图解嵌回前、第 07 阶段文章出图后独立审图；完整初稿语言修订后、文章配图前独立审文字。独立审核人只审不改，不能由制作者自审替代。阻挡与必修必须修正并验证，同一问题最多三轮；复审依实际变化确定范围，嵌图后新图说及正文改动亦须检查。报告与输入快照按下方“工作状态与审核记录”保存。两位审核人每轮都要做删减检查：文字审稿列“可删清单”（图注重复正文、事实反复出现、重复小标题、啰嗦句），审图列图内可删文字。日文版的正文与图内文字每轮都必须跑 yomiyasu lint（正文另跑 diff），报告写明分数（2026-10-30 用户要求）。

### 定稿后日文翻译（可选）

仅在 G3 后且用户要求日文时读取 [日文翻译与润色](references/translation.md)。以批准 A 版翻译，经 yomiyasu 润色、逐段原文对照及独立文字审核；用户要求日文图片时再按改图流程制作与审核。发现原文实质问题退回知识／定稿流程，纯日文措辞不重复 G3。

## 编号与版本

- **素材：** 收到的原始材料在 source.md 依来源编 M01、M02，记录名称、来源、日期、摘要和公开限制。
- **知识：** 主张、证据、案例沿用 C／E／K 编号；诊断用 D、审核问题用 Q。
- **知识基准：** 首次 G2 确认为 B1.0；实质主张、数据、案例结果或适用范围改变时升为 B2.0 并重新 G2。
- **文章：** 草稿依 A0.1、A0.2 迭代；G3 批准后为 A1.0。之后纯措辞调整记为 A1.1，实质修改重新 G3 后升 A2.0。
- **视觉：** 第 07 阶段文章通读完成后才开始 V0.1；随文章修订迭代，G3 批准后为 V1.0。每版记录依据的文章版本。
- **知识图解：** 依 G2 版本编 D-B1.0 等（与所依据的知识基准同号）；B 版升级后重画为对应新号。
- **日文版：** 记录译自哪个 A 版；不单独编主版本。
- 每个成果在 working.md 记录所用知识基准版本。版本号只记在 working.md，不混入定稿正文。

## 工作状态与审核记录

- working.md 顶部只保留简短当前状态：阶段、执行状态（进行中／待人类决定／受阻／完成）、B／A／视觉／译版版本、G1／G2／G3 对应版本与状态、未解决 Q 项、待同步文件、下一行动及其输入路径；必要时记录阻挡原因与解除条件。完成仅用于第 09 阶段出口满足时，阶段达成另记证据。历史决定仍保留在原记录，不凭页面展示或 AI 检查自动更新批准状态。
- 新报告统一保存在文章目录的 `review/`，仅在实际审核时创建；仅文章模式也用此目录。旧 `visuals/review/` 报告保留原位并继续引用，不批量改名或搬移。
- 文字报告：`review/text-review-<YYYY-MM-DD>-<lang>-<A版本>-r<NN>.md`，例如 `text-review-2026-10-28-zh-A0.3-r01.md`。
- 图片报告：`review/figure-review-<YYYY-MM-DD>-<kb|article>-<lang>-<B或A版本>-<视觉版本>-r<NN>.md`，例如 `figure-review-2026-10-28-kb-zh-B1.0-D-B1.0-r01.md` 或 `figure-review-2026-10-28-article-ja-A0.3-V0.2-r02.md`。lang 使用明确的语言标签（如 zh、zh-Hant、ja），知识图解视觉版本沿用 D-B…。
- 日期使用任务时区；同一审核类型／阶段／语言连续递增轮次，跨日期或版本也不重置。派发前检查目录及历史记录；目标已存在则递增，不能覆盖。报告内记录实际审核的正文路径、版本及 SHA-256；图片另记录每张 PNG 和可编辑来源（含依赖的 CSS／资源）的 SHA-256、视觉版本、审核范围、上一轮报告与验证结果。由执行者在派发前计算校验值，审稿人核对；校验值是版本证据，不代替阅读和看图。
- 报告 rNN 是文件的连续序号；三轮上限按 Q 项的连续修正验证次数计算，两者分开记录。不同问题映射到同一 Q 项时必须有明确理由，不能通过重编号重置仍未解决问题的计数。
- 审核输入保留对应正文的版本快照及校验值，放在 review/inputs/，以报告文件主名命名，不覆盖旧输入。知识稿嵌图会改变文件字节，即使 B 版未变也记录嵌图前后的校验值与内容核对结果；不能把旧报告的校验值改成新文件值，或仅因版本号相同宣称文件未变。
- Q 项引用“报告路径＋原始 R／T 编号”，避免不同报告中的同号问题混淆；复审逐项标明已解决／部分解决／未解决，未经验证不能关闭。上一轮有未解决阻挡或必修项时，即使文件没改也必须继续验证或退回修正。
- **图片审核范围**：无有效报告、校验值不符或无法确认原图时，按首次完整审核处理。新增或改过的图重做机械检查、逐图目视及独立七面向审核；仅正文、图说、位置变化时核对当前语境、术语、数字、限制和显示宽度。有效已审图原样复用时，用同一 PNG 与来源校验值关联旧报告，直接看图并核对新语境；未变化的视觉结论沿用，不再完整重评。新语境暴露原图问题时仍须开 Q 项，不能以“已审”忽略。全组风格、字体或输出尺寸变更会扩大受影响范围；翻译图片按改图处理。
- **现有检查工具的边界**：figure-lint 会按参照正文中已引用的 PNG 文件名筛选 HTML，目录里未嵌入的新图可能被跳过。检查前对照本轮清单与正文引用；会被漏检的图须连同相对依赖复制到临时目录，目录内只保留该图 HTML，逐图运行 figure-lint 并显式传入原参照正文路径；译版同时传对应原文图目录。记录实际覆盖清单，不能只凭一次“lint OK”宣称全部通过。warm-paper-build 内置 lint 自动寻找 article.md，不代表知识稿口径已核对；知识阶段仍须独立以 knowledge-base.md 检查。若 build 因最后的自动引用口径报错，保留日志并核实原因，只有确认错在参照且对应独立 lint、间距、风格等适用检查均通过后，才能记录为已验证；其他错误仍须修正。
- 文章需修改知识图解时，先复制 HTML、PNG 及必要依赖到 `visuals/article/`，或用户指定的独立变体目录，再修改、构建与审核；交接表记录原图、变体、两个依据版本及报告。不能原地覆盖仍被知识稿使用的图。原图本身有事实错误时，按引用对照同时修正知识稿及相关变体，并重新核验原报告的适用性。
- 修改前在现有记录列出受影响正文、知识图解、文章图、HTML、译版及 PPT；逐项验证后清除待同步标记。修改原因简记为事实补充／内容探索／文字理解／图文不符／同步遗漏／排版问题／规则冲突，允许补充；内容探索不计为执行错误。不新增工时打卡或评分表，后续用实际记录检验审稿前移是否减少配图返工。

## 文件与最终交付

默认在项目 `exports/articles/<文章短名>/` 保存；用户指定位置优先。同名任务先检查既有文件，修订保留旧稿或修改记录。

使用 [工作与交付模板](references/templates.md) 按需保存：

- `source.md`：收到的原始材料与来源。
- `working.md`：设置、诊断、评论、当前阶段、大纲、审核及修改记录。
- `knowledge-base.html`：基础知识稿的主要审阅交付，包含完整事实、观点、证据、案例、版本与确认状态；第04阶段起生成，G2 后将通过审核的所选知识图解嵌回对应章节，保持单文件离线可读，优先打开／链接HTML。
- `knowledge-base.md`：同一知识稿的可维护文本来源；每次修订同步HTML，不只输出Markdown，也不把摘要当成完整知识稿。
- `article.md`：文章初稿至定稿，必要时保留版本副本。
- `article.html`：供人类阅读的单文件版，由 `python3 <skill>/scripts/md2html.py article.md article.html` 从 article.md 生成（标题下自动放可点击目录，列出全部 ## / ### 标题）；每次改 article.md 后重跑，不手改 HTML。
- `article.ja.draft.md`／`article.ja.md`：仅在定稿后要求日文时创建；前者为直接译稿，后者为 yomiyasu 润色后的日文交付版。
- `knowledge-notes.md`：最终摘要、可重用案例、来源、适用条件与确认状态。
- `visuals/`：仅选配图或 PPT 时创建，保存真实文件、可编辑来源及图说／备注。
- `visuals/diagrams/`：G2 后的知识图解（每章 HTML＋PNG）及 `README.md`，由知识稿引用；文章原样复用可引用同一图档。
- `visuals/article/`：仅在文章需要改动知识图解时保存独立变体及必要依赖，避免改掉知识稿原图；其他新作图继续按所选 Skill 的目录保存。
- `review/`：新建的独立文字与图片审核报告，文件名、版本证据及轮次按“工作状态与审核记录”；每轮一份，不覆盖。旧 `visuals/review/` 仅保留历史报告。

在对应阶段才创建文件，不预建空成果。仅文章模式不生成视觉；缺少生成工具时说明具体缺项，完成可做部分，不标记最终交付完整。

基础知识稿HTML使用单文件、离线可读、手机友好的排版，带章节导航及打印样式。正文与来源内容一致，区分候选知识、已确认内容、待确认事项和编辑备注。G2批准来自真实人类回复，页面展示或按钮不能自动代表确认。

完整基础知识稿采用“分类标题＋分点条列”：每点表达一个事实、职责、行动、判断或结果，可用简短加粗标签帮助定位。复杂内容按意义分组，最多两层列表；不以大段散文呈现，也不把多件事挤在一条。不删掉必要说明、条件和来源。此格式用于知识稿审阅，正式文章仍采用自然连贯、有长短节奏的文字。

交付时链接实际文章、所选视觉和知识记录，简述修订及待确认事项。定稿与公开发布分别记录，没有发布指示时保存文件即可。
